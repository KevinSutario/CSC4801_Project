# T24 · Employer views an applicant's CV (own jobs only)

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 6 | EMP (P2) | CC02, T23 | yes (reads candidates) | BLOCKED until CC02 + T23 merge |

## Goal
On the applicants page for one of their own jobs (T15), an employer sees a "View CV" link for each
applicant who uploaded a PDF, and can open/download that PDF. Access is scoped to the applicants of
the employer's **own** jobs; any other employer or a candidate gets `403`, and the graded owner-only
direct resume URL (T23) is left untouched.

## Requirement
The 2026-11-24 clarification, "Employer viewing an applicant's resume":
> You are encouraged to let the employer of the job the candidate applied to view their resume. This
> is **not graded** as it is not clearly specified, and showing or not is not a valid peer-audit
> finding.

So this card is **encouraged, ungraded** polish. It must not change any graded behaviour: FP-EMP-3
fields/order/status (T15) and the FP-CAN-1 owner-only direct URL (T23) stay exactly as they are. This
card adds a *separate* employer route; it does not touch the candidate `resume_file_view` route.

## Decided (D23)
- New employer route, not a reuse of the candidate URL. Ownership is checked employer-side: the
  employer must own the job that this application belongs to (same `get_owned_job`/company-owner
  check T15 already uses), else `Forbidden`; a missing application or an applicant with no file is
  `NotFound`.
- The file is read through P1's authz-free helper `resolve_resume_file` (T23); P2 does its own
  ownership check first, then streams. P2 does **not** edit `resume_service.py`.
- Graded FP-EMP-3 fields (identity, skills, score, status, booking) already ship in T15 and are not
  changed here — the applicants dict keeps exactly its current keys (no `resume_id`). The link is
  built in the template from `candidate_id`, nothing is added to `list_applicants`.

## Contract (add to 07-CONTRACTS.md under applications via CC02)
```python
def resolve_applicant_resume(conn, employer_id: int, application_id: int) -> dict
    # load application -> job -> company; Forbidden unless company.owner_id == employer_id
    # (ownership before existence); NotFound if the application is missing or the candidate has no
    # CV file; else the file row + absolute path (via resume_service.resolve_resume_file).
```
Route: `applications.applicant_resume` GET `/employer/applications/<int:application_id>/resume`,
`@login_required`, `@role_required("employer")`. Streams the PDF (`send_file`,
`mimetype="application/pdf"`, `download_name` = the applicant's original filename).

## Steps
1. Test first (the ownership logic needs test-first).
2. `resolve_applicant_resume` in `review_service.py`: one query joining
   `applications → jobs → companies` to get `company.owner_id` and the `candidate_id`. Raise
   `Forbidden` unless `owner_id == employer_id` (before existence). Then call
   `resume_service.resolve_resume_file(conn, candidate_id)`; `NotFound` if the application does not
   exist or that returns `None`. Return the file row + path.
3. Route `applications.applicant_resume`: call the helper, `send_file(path, mimetype=..., as_attachment=False, download_name=original_name)`.
4. `applicants.html`: in each row, where the identity/skills cells already render, add a "View CV"
   link to `url_for("applications.applicant_resume", application_id=row.application_id)` — only shown
   when the row indicates a file exists. To know that without changing `list_applicants`' keys, the
   template may call nothing extra; instead render the link for every row and let the route return
   404 if absent, OR (preferred) P2 confirms with the owner before adding a `has_cv` boolean. Keep
   the graded keys unchanged; if a `has_cv` flag is wanted, raise it as a tiny CC note, do not invent
   a key silently.
5. Leave `list_applicants`, `set_status`, order and the four statuses untouched (graded, T15).

## Pitfalls
- This is ungraded: do not let it regress the graded T15 fields/order or the T23 owner-only URL.

- Do the employer ownership check in P2's code; never reach the file through the candidate's
  owner-only route. `resolve_resume_file` is authz-free by contract — guarding it is this card's job.
- Do not edit `app/candidates/resume_service.py`; only read it. Need a change there? Ask P1.
- Do not add keys to the `list_applicants` dict without a CC note — the key set is graded (D11).
