# T10 · Jobs: create, edit, delete, detail

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 2 | EMP | T09 | no | READY (limits are DEFAULT (not in brief)) |

## Goal
An employer can post, edit and delete jobs with required skills. Anyone signed in can view a job's
detail page.

## Requirement
FP-EMP-2: job validation and deletion. Rule text (brief section "4. Employer workflow", FP-EMP-2
"Job postings"):
> An employer **MUST** be able to create, view, edit, and delete their own job postings. Each posting **MUST** contain a non-empty title and description plus a required-skills list; the list may be empty. An employer **MUST** receive `403` when attempting to edit, delete, or manage applicants for another employer's posting.
>
> A job with no applications or interview slots **MUST** be deletable. If either kind of dependent record exists, deletion **MUST** fail with `409 Conflict` (or a clearly documented equivalent) and leave the job and dependent records unchanged.

Decided (per the quote):
- Skills (D12): "the list may be empty". A job with no skills is valid (FP-MATCH-1 scores it 100 for
  every candidate). Skills 0 to 30 (30 is DEFAULT).
- Delete (D12): no cascade. If the job has any application, deletion fails with `409 Conflict` and
  changes nothing (interview slots are employer-owned since CC01, so applications and their bookings
  are a job's only dependants).
- Another employer's job (D9): `403 Forbidden`, not 404.
- No closed state (D18): jobs have no open/closed flag; every job that exists is current and
  listable (FP-CAN-2). `jobs.detail` is `@login_required` and shows any job.

DEFAULT (not in brief): title max 120 chars; description max 5000; location max 80; employment type
one of `EMPLOYMENT_TYPES = ("full-time", "part-time", "contract", "internship")`; salary min and max
optional whole numbers from 0 to 10_000_000, min <= max; at most 30 skills.

## Steps
1. Tests first.
2. A private `_validate(...)` returns cleaned values or raises `ValidationError` with all field
   errors. Salary: empty string means None; otherwise `int()` inside `try`; reject non-numbers.
3. `create_job`: employer must have a company (`ValidationError({"company": "Create your company
   profile first."})`). Insert job and `job_skills` in one transaction. Audit `job.create`.
4. `get_owned_job`: select where `jobs.id = ?`; `NotFound` if missing; `Forbidden` if
   `companies.owner_id` is not the employer.
5. `update_job`: use `get_owned_job` first, audit `job.update`. `delete_job`: use `get_owned_job`
   first, then `count_dependants(conn, job_id)` (applications on the job); if it is greater than 0
   raise `Conflict` and change nothing; else delete and audit `job.delete`.
6. `list_jobs`: one query for jobs with company name, one query for all their skills, then group
   in Python (no query per job). Lists every job (no closed state).
7. Routes and templates: list (with empty state), form (new and edit share `jobs/form.html`), a
   confirm-delete page that says either "This job has no applications and can be deleted" or "This
   job has N applications and cannot be deleted" (no delete button then); `jobs.delete` POST returns
   409 via `Conflict` when there are dependants; detail page with skills as badges and a link "Apply
   to this job" to `/jobs/<id>/apply` (T14 builds it). Every POST form includes `csrf_field()`
   (04-AUTH-SECURITY.md).
