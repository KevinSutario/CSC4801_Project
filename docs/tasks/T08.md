# T08 · Resume upload, list, delete, private download

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|

## Goal
A candidate can enter a raw-text resume, view it, and replace it. Only the owner can read it; any
other candidate or employer gets 403.

## Requirement
FP-CAN-1 (private resume rules). Rule text (brief section "3. Candidate workflow", FP-CAN-1
"Candidate profile and resume", second paragraph):
> A candidate **MUST** be able to enter a raw-text resume. The application **MUST** persist the text and allow the owner to view and replace it. PDF upload and extraction are optional. Resume contents are private: only the owning candidate may read or modify them. Any other candidate or employer **MUST** receive `403` through a direct URL/API request.

Decided (D10): the resume is raw text, one per candidate, owner-only. There is no file upload and no
employer access. A missing-or-not-yours view gives 403 (`get_resume_for_viewer` checks ownership
before existence).

DEFAULT (not in brief): resume body at most `RESUME_MAX_CHARS` (20000) characters.

## Contract
```python
def get_resume(conn, owner_id: int) -> dict | None      # keys: owner_id, body, updated_at
def save_resume(conn, owner_id: int, body: str) -> None
    # strip; ValidationError({"body": ...}) if empty or over RESUME_MAX_CHARS; upsert; audit resume.update
def get_resume_for_viewer(conn, viewer_id: int, candidate_id: int) -> dict
    # Forbidden unless viewer_id == candidate_id; then NotFound if that candidate has no resume
RESUME_MAX_CHARS: int = 20000     # DEFAULT (not in brief)
```
Routes: `candidates.resume` GET/POST `/candidate/resume` (candidate only: shows the current text in
a textarea, POST replaces it); `candidates.resume_view` GET `/candidates/<int:candidate_id>/resume`
(`@login_required`, any role: the owner sees their text, anyone else gets 403).

## Steps
1. Tests first.
2. `get_resume`: read the `resumes` row for `owner_id`, return `None` if there is none.
3. `save_resume`: strip the body; `ValidationError({"body": ...})` if empty or over
   `RESUME_MAX_CHARS`; upsert the single row (`INSERT ... ON CONFLICT(owner_id) DO UPDATE`) in a
   transaction; audit `resume.update`.
4. `get_resume_for_viewer`: raise `Forbidden` unless `viewer_id == candidate_id` (ownership is
   checked before existence); then raise `NotFound` if that candidate has no resume; else return the
   row. SQL with `?` placeholders.
5. Resume page: a form with one textarea showing the current body, POST replaces it. Every POST form
   includes `csrf_field()`. Privacy line: "Only you can read your resume."
6. View route `candidates.resume_view`: renders the owner's text, escaped by Jinja autoescape.

## Tests (`tests/unit/test_can_resume.py`; remove the skip on the template test)
- `test_fp_can_1_profile_and_private_resume_rules`: profile saved (through `profile_service`);
  `save_resume` then `get_resume` returns the text; a second `save_resume` replaces it (one row);
  empty body and a body over `RESUME_MAX_CHARS` rejected; owner GET `/candidates/<own id>/resume`
  gives 200 with the text; another candidate gets 403; an employer gets 403; owner with no resume
  gets 404; a body of `<script>alert(1)</script>` is rendered escaped (the raw tag never appears in
  the response).

## Pitfalls
- The resume is raw text only; no file is ever written to disk.
- Ownership is checked before existence, so a non-owner always gets 403, never 404.
