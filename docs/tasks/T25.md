# T25 · Seed a demo CV file for a demo candidate

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 6 | PLATFORM (P3) | T23 | no | BLOCKED until T23 merges |

## Goal
After `python scripts/seed.py --reset`, one demo candidate has a CV PDF attached through the real
`save_resume_file` service, so the upload feature (T23) and the employer view (T24) are both
demonstrable on fresh demo data without anyone uploading a file by hand.

## Requirement
Supports FP-DOC-3 (demo data) and the 2026-11-24 CV-file clarification. Seed data must go through the
real services so it always obeys the rules (the existing `seed.py` contract, T19). No new business
rule here — this card just adds demo content for the T23 feature.

## Decided (D23)
- Reuse the real service: call `save_resume_file(conn, <candidate_id>, <file_storage>)` exactly as
  the upload route would, so the seeded file validates as a PDF and writes to `UPLOAD_DIR` like a
  real upload. Do not insert into `resume_files` directly.
- Attach the CV to the demo candidate who already gets a text resume (`meilin`), so one demo
  candidate shows both a text resume and a CV file. The others stay file-less (so the "no CV" path
  is also demonstrable).
- The demo PDF is a tiny fictional fixture committed with the seed, not a real person's CV.

## Owns
- `scripts/seed.py`
- `scripts/fixtures/demo_cv.pdf`   (new; a minimal valid PDF, a few hundred bytes)

## May read
- `CLAUDE.md`, `AGENTS.md`
- `docs/plan/12-DEPLOY.md` (FP-DOC-3 demo minimum)
- `docs/plan/07-CONTRACTS.md` (candidates: resume — `save_resume_file` from CC02/T23)
- `app/candidates/resume_service.py` (read `save_resume_file`'s signature; it takes a file-like
  `file_storage` with `.filename`, `.content_type`, `.read()/.save()`), `app/config.py` (UPLOAD_DIR)

## Steps
1. Add `scripts/fixtures/demo_cv.pdf`: a minimal valid single-page PDF (starts with `%PDF-`). Keep it
   tiny and clearly fictional ("Demo CV — fictional person").
2. In `seed.py`, where `save_resume` is already called for `meilin`, also build a `FileStorage`
   (or the simplest object `save_resume_file` accepts — check its real signature first, AGENTS.md
   rule 2) wrapping `scripts/fixtures/demo_cv.pdf` with filename `demo_cv.pdf` and content-type
   `application/pdf`, and call `save_resume_file(conn, meilin, that)`. Resolve the fixture path from
   `__file__`, never a hard-coded absolute path.
3. Keep the rest of the seed unchanged; `--reset` behaviour and the "refuse if users exist" guard
   stay as they are.

## Tests
- No new unit test is required (seed is exercised by the deploy/seed path). If `test_seed` or an
  equivalent exists, extend it to assert `get_resume_file(conn, meilin)` is not `None` after seeding
  and that exactly that one demo candidate has a CV. Otherwise, the hand-off must paste a real
  `python scripts/seed.py --reset` run showing the CV was attached (no traceback).

## Done when
- `python scripts/check.py` passes (paste output)
- `python scripts/check_scope.py T25` passes
- `python scripts/seed.py --reset` runs clean and `get_resume_file` returns the demo file for the
  chosen candidate (paste the check)

## Pitfalls
- Call `save_resume_file`; do not write the `resume_files` row or copy the file by hand — that would
  bypass validation and could drift from the real behaviour.
- Quote `save_resume_file`'s real parameter type before building the fake upload object; if it only
  accepts a Werkzeug `FileStorage`, construct one (`werkzeug.datastructures.FileStorage`) rather
  than guessing an interface.
- The fixture must be a real valid PDF (first bytes `%PDF-`) or T23's validator will reject it.
- Do not touch `app/schema.sql` or `resume_service.py` — those are CC02 and T23.
