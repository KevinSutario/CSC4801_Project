# T26 · Add a View applicants link to My jobs

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 6 | EMP (P2) | T10, T15 | no | READY (both dependencies MERGED) |

## Goal
Each job card on the employer's My jobs page (`jobs.my_jobs`, `app/templates/jobs/list.html`) shows a
"View applicants" link next to Edit and Delete, pointing at the existing FP-EMP-3 applicant-management
page (`applications.applicants`, T15) for that job. The employer no longer needs to type the
`/employer/jobs/<job_id>/applicants` URL by hand.

## Requirement
FP-EMP-3 (brief section "4. Employer workflow", "Applicant management"):
> For each owned job, an employer **MUST** be able to view its applicants sorted by match score from
> highest to lowest.

The applicant-management page itself already exists and is graded (T15, MERGED). This card is a
navigation gap only: the employer's job list never links to it. No new business rule, no new route,
no contract change — the link reuses the existing endpoint with the job's own `job.id`.

No new names, routes, or signatures. Nothing is added to `scripts/contracts.json` or
`07-CONTRACTS.md`. The card only renders a link in an owned template to the existing route
`applications.applicants` GET `/employer/jobs/<int:job_id>/applicants` (T15, unchanged).

## Steps
1. Write the regression test first (below), run it, show it failing: the employer's job list response
   contains no link to `/employer/jobs/<job_id>/applicants`.
2. In `app/templates/jobs/list.html`, in the `job-actions` paragraph where `Edit` and `Delete` already
   render, add a "View applicants" link button between them (or beside Edit) using the existing
   `link_button` macro:
   `{{ link_button("View applicants", "/employer/jobs/" ~ job.id ~ "/applicants") }}`
   Use the same hand-built URL style as the neighbouring Edit/Delete links; do not invent a new
   helper. `job.id` is already in the `list_jobs_for_employer` rows (the Edit/Delete links use it).
3. Render the link for **every** owned job card, including jobs with zero applications — the
   applicants page already has the empty state "No one has applied to this job yet."
   (`app/templates/applications/applicants.html:7`), so no conditional is needed.
4. Change nothing else: not the public job detail page (`jobs/detail.html`), not
   `jobs/service.py` or `jobs/routes.py`, not authorization (`applicants` stays
   `@role_required("employer")` with the T15 ownership check), not CV handling (T23/T24), and not
   any response contract.

## Pitfalls
- Template-only change: do not touch `app/jobs/routes.py`, `app/jobs/service.py`, or anything under
  `app/applications/` — those are T10/T15 files and `tests/unit/test_emp_applicants.py` is owned by
  the in-flight T24. The regression test goes in `tests/unit/test_emp_jobs.py`.
- Build the URL from that row's `job.id`, never a hard-coded id — the test must catch a link that
  points at the wrong job.
- Show the link even when the job has no applications; do not query application counts (that would
  add per-job queries and break the fixed-query-count guarantee of the list page).
- Do not add an "applicants" link to the public job detail page — that page is for candidates.
- No contract change: if you find yourself wanting a new route, service function, or template
  variable, stop and raise a CC note instead.
