# T12 · Time zone helpers and interview slots

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 2 | SCHED | T05 | no | READY (rules quoted from the brief; the rest DEFAULT (not in brief)) |

## Goal
Employers add interview slots in their own time zone. Slots belong to the employer (not a job),
are stored in UTC and shown correctly in any time zone. Invalid slots are rejected.

## Requirement
FP-SCHED-1: slot creation, timezones and deletion; invalid slots. Rule text (brief section
"6. Applications and interview scheduling", FP-SCHED-1 "Availability"):
> An employer **MUST** be able to create and delete future, 30-minute availability slots. Each slot **MUST** have one owner and an exact start and end time with an unambiguous, documented timezone. The system **MUST** reject invalid durations, end-before-start values, and deletion of a booked slot. Booked slots **MUST NOT** be shown as available.

Worked examples: none in the brief for FP-SCHED-1.

Decided (D13): a slot belongs to the **employer**, not a job (`interview_slots` has no `job_id`).
Duration is exactly 30 minutes (29 and 31 minutes are invalid). Start must be in the future; end
after start; a booked slot cannot be deleted (`Conflict`, 409 is DEFAULT (not in brief)); booked
slots are never listed as available. Deleting another employer's slot gives `Forbidden` (D9).

DEFAULT (not in brief): date `YYYY-MM-DD`, times `HH:MM` 24-hour; no overlap with another slot of
the same employer; storage in UTC with the entry zone recorded (the brief only requires "an
unambiguous, documented timezone", so document it in SPEC.md).

## Contract
`app/timeutil.py` and `app/scheduling/slots.py` exactly as in `07-CONTRACTS.md`. Routes
`scheduling.slots` GET/POST `/employer/slots`, `scheduling.delete_slot` POST
`/employer/slots/<int:slot_id>/delete`, both `@role_required("employer")`.

Slots are owned directly by the employer (`interview_slots.employer_id`); there is no job ownership
query.

## Steps
1. Tests first.
2. `timeutil`: use `zoneinfo.ZoneInfo`. `validate_tz` raises `ValueError` for unknown names (catch
   `ZoneInfoNotFoundError` and `ValueError`). `local_to_utc`: parse with `datetime.strptime`, attach
   the zone, convert to UTC, then convert back and compare with the input; if different, the time does
   not exist (DST gap): `ValueError`. Output format `%Y-%m-%dT%H:%M:%SZ`. `COMMON_TIMEZONES`: UTC,
   Asia/Hong_Kong, Asia/Shanghai, Asia/Jakarta, Asia/Singapore, Europe/London, America/New_York.
3. `create_slot`: validate every field (collect errors), duration exactly 30 minutes, future start
   (compare with `now_iso()` as strings is fine: same format), overlap query against the employer's
   own slots (`employer_id = ? AND starts_at < ? AND ends_at > ?`), insert, audit `slot.create`.
4. `delete_slot`: `NotFound` if missing; `Forbidden` if another employer's; booked: `Conflict`;
   else delete, audit `slot.delete`.
5. `list_slots_for_employer`: one query with `LEFT JOIN bookings`, `booked` as bool, start ascending.
6. Page (reached from the employer home): add-slot form (date, start, end, time zone select
   defaulting to the employer's last used zone or UTC), list in the chosen zone, delete button only
   on unbooked slots. A slot's time range label is composed in the template from two `utc_to_local`
   calls (`format_local` stays a single-time formatter). Every POST form includes `csrf_field()`
   (04-AUTH-SECURITY.md).
