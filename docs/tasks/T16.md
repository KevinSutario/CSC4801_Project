## Goal
An eligible candidate sees the open slots for their application, in their time zone, and books one
through a confirm screen. Ineligible candidates cannot book.

## Requirement
FP-SCHED-2: eligible and ineligible booking. Rule text (brief section "6. Applications and
interview scheduling", FP-SCHED-2 "Booking eligibility"):
> The system **MUST** allow a candidate to book a slot if and only if all of the following are true:
>
> - the candidate owns the application;
> - the slot belongs to the employer for the candidate's application;
> - the application status is `Interviewing`;
> - the slot is in the future and is not already booked; and
> - the application has no existing booking.
>
> A successful booking **MUST** link the candidate's application to the slot and be visible to both that candidate and the owning employer. Ineligible bookings **MUST** fail without partially changing either record. If a booked application later leaves `Interviewing`, its booking **MUST** remain associated with the application and the slot **MUST** remain unavailable.

Worked examples: none in the brief for FP-SCHED-2.

Decided (D13):
- Eligible means all five bullets, with the status being the literal `interviewing`.
- A slot belongs to the **employer** who owns the application's job (not to a job): `interview_slots`
  has no `job_id`, so any future, unbooked slot of that employer is bookable.
- One booking per application ("the application has no existing booking"), enforced by the
  `uq_booking_application` index.
- Leaving `interviewing` later: the booking stays and the slot stays unavailable.
- Another candidate's application (D9): `get_own_application` raises `Forbidden` (a missing one is
  `NotFound`).

## Contract
```python
def is_eligible(conn, candidate_id: int, application_id: int) -> bool
def list_bookable_slots(conn, candidate_id: int, application_id: int) -> list[dict]
def book_slot(conn, candidate_id: int, application_id: int, slot_id: int) -> int
```
Routes: `scheduling.application_detail` GET `/candidate/applications/<int:application_id>`;
`scheduling.confirm_booking` GET and `scheduling.book` POST
`/candidate/applications/<int:application_id>/book/<int:slot_id>`, all `@role_required("candidate")`.

## Steps
1. Tests first, using the brief's rule.
2. `is_eligible`: `get_own_application` (raises `NotFound` if missing, `Forbidden` if another
   candidate's), then returns True only if status is `interviewing` and the application has no
   booking yet.
3. `list_bookable_slots`: future, unbooked slots of the employer who owns the application's job,
   start ascending.
4. `book_slot` (simple version; T17 hardens it): `NotFound` if the application or slot is missing;
   `Forbidden` if the application is another candidate's, or status is not `interviewing`, or the
   application already has a booking, or the slot belongs to another employer, or the slot is in the
   past; inside `transaction(conn, immediate=True)`: insert booking, audit `booking.create`. No
   booking row is written on any failure.
5. Detail page: application status, then either "Book an interview" with slots shown in the
   candidate's time zone (from `get_profile`) with the zone name, or the booked slot, or a line
   explaining why booking is not open (not eligible).
6. Confirm page: `confirm_box` with the slot's 30-minute range in the candidate's zone and in the
   employer's `created_tz`, and the job. POST books, redirects to the detail page with a flash.
   Every POST form includes `csrf_field()` (04-AUTH-SECURITY.md).
