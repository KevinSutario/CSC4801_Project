# B5 · Login rate limit bypassed by rotating IP (per-email limit missing)

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 5 | security | T22 audit | no | DONE (merged into dev at e0919f1) |

## Symptom
Distributed brute force against one account is unthrottled: 5+ wrong-password attempts on the same
email, each from a different source IP, never lock (all 400 bad-creds); only repeats from the SAME
IP lock (429 after 5). Found by the T22 security audit.

## Cause (one sentence)
`app/auth/routes.py` throttles on a single combined key `login_key(email, ip)` = `"email|ip"`, so
every new IP gets a fresh 5-attempt bucket; `docs/plan/04-AUTH-SECURITY.md` requires a limit "per
email AND per IP". `app/security.py` is a frozen T01/T02 file, but its limiter primitives
(`login_key`, `is_login_blocked`, `record_failed_login`, `reset_login_failures`) are key-agnostic,
so the fix lives entirely in the (non-frozen) auth route.

## Fix
In the login route, track two keys built from the existing `login_key`:
`email_key = login_key(email, "")` and `ip_key = login_key("", ip)`. Block when EITHER is blocked;
on a failed attempt record BOTH; on success reset BOTH. This enforces per-email and per-IP limits
with the existing primitives, no change to the frozen security module.

- Keep the existing single-IP 429 test green.
