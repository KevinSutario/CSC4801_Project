# B4 · Docker: PermissionError on /app/instance at container start

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 4 | delivery | T20 | no | FIXING (P2) |

## Symptom
`docker run --rm -p 8080:8080 keystone` crashes on start:
```
PermissionError: [Errno 13] Permission denied: '/app/instance'
  at create_app() -> os.makedirs(app.instance_path, exist_ok=True)
```
Found during the Phase-4 gate (real docker build/run). Unit tests and the non-Docker container-style
launch did not catch it because they set DATABASE/UPLOAD_DIR outside /app.

## Cause (one sentence)
`WORKDIR /app` creates `/app` owned by root; the container runs as `student`; `create_app()`
unconditionally does `os.makedirs(app.instance_path)` (= `/app/instance`), which `student` cannot
create under the root-owned `/app`. The Dockerfile only chowned `/app/data`, not `/app/instance`.
`app/__init__.py` is a frozen T01 file, so the fix must be in the Dockerfile (T20's Owns).

## Fix
In `Dockerfile`, create and chown `/app/instance` alongside `/app/data` before `USER student`, so
`create_app()`'s `makedirs(instance_path, exist_ok=True)` succeeds.

## Owns
- `Dockerfile`

## Verification
Infra/Dockerfile change; no unit test can exercise container file permissions (the test env has no
Docker). Verified by a real `docker build` + `docker run` reaching "Serving on http://0.0.0.0:8080"
and signing in as a demo account. `python scripts/check.py --release` still passes (unchanged code).
