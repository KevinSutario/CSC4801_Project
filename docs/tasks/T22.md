## Goal
Find the bugs other teams would find, before they do. Review agents only; fixes go through bug cards.

## How the orchestrator runs it
This card is not given to an implementer. The orchestrator runs it with `/review-task` in four
areas, each with three reviewers and the judge, against `main`:

| Area | Packet focus | Reviewer prompt addition |
|---|---|---|
| Security | auth, security, every route with an id, uploads | "You are another team auditing for `type:security` bugs. Use the 12-line checklist. Try to break in." |
| Functional | every FP-* requirement against `docs/BRIEF.md` | "You are another team auditing for `type:functional` bugs. For each requirement, find an input where the app does not do what the brief says." |
| Performance | recommendations, applicants, lists | "You are another team auditing for `type:performance` bugs on a small fixture: queries in loops, missing indexes, loading everything." |
| Delivery | README, SPEC, INSTALL, Dockerfile | "Follow INSTALL.md exactly from a fresh clone. Report every step that fails or is unclear." |

For each area:
```
git worktree add --detach ../ks-audit main      (once)
python scripts/make_packet.py audit security    (then functional, performance, delivery)
/review-task audit security
```
The reviewer prompt gets the addition from the table above as one extra line.

Extra judge step: the performance smoke test from `11-TESTING.md` (200 jobs, 200 candidates, each
page under 1 second).

## After
- Every CONFIRMED finding becomes a card `Bxx` via `/bugfix`.
- Gate: `python scripts/check.py --release` passes, no open `Bxx`, no `xfail` left.
