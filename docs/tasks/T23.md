# T23 · Candidate CV file upload (alongside the text resume)

| Phase | Lane | Depends on | Joins lanes | Status |
|---|---|---|---|---|
| 6 | CAN (P1) | CC02 | no | BLOCKED until CC02 merges |

## Goal
On top of the existing raw-text resume (T08), a candidate can upload one **PDF CV file**, see its
name and replace or remove it, and download their own file. The file is private: a direct download
URL for anyone other than the owner gives `403`, exactly like the text resume (FP-CAN-1, graded).

## Requirement
FP-CAN-1 (candidate workflow) + the 2026-11-24 clarification. Rule text
(brief section "3. Candidate workflow", FP-CAN-1 second paragraph):
> A candidate **MUST** be able to enter a raw-text resume. The application **MUST** persist the text
> and allow the owner to view and replace it. PDF upload and extraction are optional. Resume contents
> are private: only the owning candidate may read or modify them. Any other candidate or employer
> **MUST** receive `403` through a direct URL/API request.

Clarification (graded part):
> Direct resume URL/API (FP-CAN-1): only the owning candidate may read or edit it. Everyone else
> gets 403. This is graded.

So the CV file is the "optional PDF upload"; because it is a resume content, its direct download URL
inherits the **graded** owner-only 403 rule. The text resume path from T08 is unchanged.

## Decided (D23)
- File is additive, never replaces the text resume. One PDF per candidate, on disk under
  `UPLOAD_DIR`, metadata in `resume_files` (CC02). PDF only, at most `MAX_UPLOAD_MB` (2).
- Owner-only direct download (403 for everyone else incl. employers and a missing id, before
  existence — mirrors `resume_view`, D10). Employer access is a different, ungraded route (T24).
- Audit via existing `resume.update` action (CC02); no new audit action.

Routes (all under the existing `candidates` blueprint):
- `candidates.resume_file` POST `/candidate/resume/file` — `@login_required`, `@role_required("candidate")`; upload, replaces any existing file, flash + redirect to `/candidate/resume`.
- `candidates.resume_file_delete` POST `/candidate/resume/file/delete` — same guards; removes the file.
- `candidates.resume_file_view` GET `/candidates/<int:candidate_id>/resume/file` — `@login_required`, any role; owner streams the PDF; anyone else 403; owner-with-no-file 404.

## Steps
1. Tests first (the logic — validation + ownership — needs test-first per AGENTS.md rule 9).
2. `save_resume_file`: read `file_storage` (a Werkzeug `FileStorage` from `request.files`). Reject if
   missing/empty filename, extension not `.pdf`, content-type not `application/pdf`, or first bytes
   are not `%PDF-` (`ValidationError({"file": ...})`). Enforce size ≤ `MAX_UPLOAD_MB` (Flask's
   `MAX_CONTENT_LENGTH` already 413s oversized bodies; also check `size_bytes`). Generate
   `stored_name` with `secrets.token_hex` + `.pdf` (never the user's name — path-traversal). Save to
   `current_app.config["UPLOAD_DIR"]`. If a previous file exists, delete its disk file. Upsert the
   `resume_files` row (`INSERT ... ON CONFLICT(owner_id) DO UPDATE`). `log_event` `resume.update`.
3. `get_resume_file` / `delete_resume_file` / `resolve_resume_file`: straight SQL with `?`
   placeholders; delete removes row and disk file.
4. `get_resume_file_for_viewer`: raise `Forbidden` unless `viewer_id == candidate_id` (ownership
   before existence); then `NotFound` if no file; else return the row + absolute path.
5. Routes: upload/delete use `request.files` / POST, `csrf_field()` in the form; view route uses
   `flask.send_file`/`send_from_directory` with `as_attachment=False`,
   `download_name=original_name`, `mimetype="application/pdf"`.
6. `resume.html`: below the existing textarea form add a small "CV file (PDF, optional)" section:
   if a file exists show its `original_name` + a "Download" link (to `resume_file_view` with the
   owner's own id) and a "Remove" POST button; always show an upload form
   (`<input type="file" name="file" accept="application/pdf">`, `enctype="multipart/form-data"`,
   `csrf_field()`). Keep the privacy line. Do not change the read-only text branch used by `resume_view`.

## Pitfalls
- `stored_name` is server-generated; never build a path from the uploaded filename (path traversal).
- Ownership is checked before existence, so a non-owner always gets 403, never 404 (matches T08/T06).
- Do not add a new audit action — use `resume.update` (frozen `audit.py`).
- Do not touch `app/schema.sql` — CC02 added the table. If you need a column that isn't there, stop
  and ask P2 for a CC card.
- Delete the old disk file on replace so `UPLOAD_DIR` does not leak orphans.
